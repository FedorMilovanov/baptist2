> **Статус GitHub на 4 ноября 2026 года: исходники приложения отсутствуют.**
> Этот репозиторий содержит документы передачи проекта, конфигурацию React/Vite и
> `package-lock.json`, но не содержит каталога `src/`. Поэтому его **нельзя
> считать работающим или собираемым приложением**, хотя исторические записи
> в `ROADMAP.md`, `HANDOFF.md` и `TRANSFER.md` описывают ранее выполненную
> работу в другой среде. Не трактуйте такие записи как подтверждение текущей сборки.

## Назначение

Рабочие и исторические заметки для исследовательского прототипа интерактивной
карты истории русского баптизма: предполагаемые 3D-связи, хронология, таблицы
деятелей и организаций, викторины с объяснениями и первоисточниками.

Это **не демонстрация готового сайта** и не база проверенных фактов:
исторические утверждения в передаточных документах требуют самостоятельной
сверки с первоисточниками и точными локаторами перед публикацией.

## Что действительно находится в `main`

- `package.json`, `package-lock.json` — перечень и закреплённые версии
  зависимостей; обновлены в security PR #1 от 3 ноября 2026 года;
- `vite.config.ts`, `tsconfig.json`, `index.html` — конфигурация и
  HTML-точка входа; `index.html` ссылается на **отсутствующий** `src/main.tsx`;
- `HANDOFF.md`, `TRANSFER.md`, `ROADMAP.md`, `EXPORT_GUIDE.md` —
  *исторические* заметки и планы, не свидетельство текущего работоспособного кода;
- `SOURCE_POLICY.md` — политика источников с приоритетом архивных документов;
- `.github/workflows/dependency-security.yml` — проверка зависимостей,
  **не** проверка сборки приложения.

Контроль фактов: на `main` до добавления этого README
(`7265f5e6db8ef9a32177bc1390c84c206512b0a5`) дерево содержало
14 объектов Git и 0 исходных файлов в `src/`. В истории доступны только
начальная загрузка документации и последующее исправление зависимостей.
Рабочую сборку на этом SHA не подтверждали.

## Восстановление без подмены

1. Найти **подлинные файлы** первоначального прототипа (`src/App.tsx`,
   `src/main.tsx`, `src/index.css`, `src/components/*`, `src/data/*`)
   в исходной рабочей среде/подтверждённой резервной копии.
2. Сверить их происхождение и содержимое с `TRANSFER.md` и
   `HANDOFF.md`. Имена файлов в документации сами по себе **не
   доказывают существование** таких файлов в GitHub.
3. Переносить исходники через отдельный проверяемый PR и только затем
   выполнять чистую установку `npm ci`, `npm run build`, проверку
   интерфейса и исторических источников. Результат каждого этапа
   документировать по фактическим проверкам.
4. Если исходники не будут найдены, оставить репозиторий как
   **архив материалов**, а не генерировать фиктивное приложение ради
   зелёного CI.

**Не путать с [FedorMilovanov/baptist](https://github.com/FedorMilovanov/baptist)**:
это отдельный действующий репозиторий, в котором есть `src/` и собственные
активные PR. Копировать его код сюда без анализа, явного решения об
объединении проектов и проверки прав/истории нельзя.
