# Как сохранить проект перед падением длинной сессии

## Лучший вариант: GitHub

1. Создать публичный или приватный репозиторий GitHub.
2. Загрузить туда реальные файлы проекта, сохраняя структуру папок.
3. В новую AI-сессию дать ссылку на репозиторий.
4. Попросить новую сессию сначала прочитать:
   - `HANDOFF.md`
   - `SOURCE_POLICY.md`
   - `ROADMAP.md`
   - `package.json`
   - `src/App.tsx`
   - `src/data/*`

Это лучше, чем один огромный текстовый файл.

## Если можно загрузить только текстом

Создать набор `.txt` файлов, где каждый файл соответствует одному исходному файлу:

```text
path: src/App.tsx
---
...содержимое файла...
```

Не объединять всё в один мегатекст, если можно избежать.

## Минимальный набор для восстановления

Если нет возможности передать всё, передать сначала:

1. `package.json`
2. `vite.config.ts`
3. `tsconfig.json`
4. `index.html`
5. `src/main.tsx`
6. `src/index.css`
7. `src/App.tsx`
8. `src/data/*`
9. `src/components/Navigation.tsx`
10. `src/components/Hero.tsx`
11. `src/components/MindMap3D.tsx`
12. `src/components/Quiz.tsx`
13. `src/components/Timeline.tsx`
14. `src/components/Glossary.tsx`

После этого остальные компоненты можно восстановить постепенно.

## Как объяснить новой сессии

```text
Восстанови проект по этим файлам. Сохрани структуру путей. Не переписывай package.json вручную, если зависимости уже есть. Исторические данные держи в src/data. Работай полными файлами, если patch падает. После восстановления запусти build_project.
```
