# Русский баптизм — handoff для новой AI-сессии

Этот файл нужен, чтобы новую сессию можно было быстро ввести в курс проекта без длинной истории чата.

## 1. Что это за проект

Интерактивный сайт на React/Vite/Tailwind про историю русского баптизма:

- три истока: Закавказье, Южная Украина, Петербург;
- хронология от мировых истоков баптизма до современности;
- 3D-карта связей;
- таблицы организаций и фигур;
- Quiz с объяснением ошибок;
- глоссарий-таблица;
- отдельный блок по журналу «Баптист».

## 2. Важные правила работы

1. Для крупных изменений переписывать файл целиком.
2. После 3-5 правок запускать `build_project`.
3. Если патч упал 2 раза подряд, не продолжать патчить: прочитать файл и переписать полный файл.
4. Исторические данные держать в `src/data/*`, не размазывать по компонентам.
5. Википедию не использовать как опору. Можно только как внешний ориентир, но не как source в данных.
6. Савинский — слабый источник: использовать только после сверки с другими источниками.
7. Предпочтительные источники:
   - baptist.org.ru
   - baptistru.info
   - pravenc.ru
   - mbchurch.ru
   - журнал «Баптист»
   - «Братский вестник»
   - архивные протоколы съездов (ГМИР, фонд В.Г. Павлова)
   - Coleman 2007 для внешнего англоязычного академического контекста

## 7. Как передавать проект в новую сессию

Лучший способ:

1. Залить проект в GitHub как обычный репозиторий, НЕ как один огромный текст.
2. В новой сессии дать ссылку на GitHub.
3. Сказать: «Прочитай HANDOFF.md, ROADMAP.md, SOURCE_POLICY.md, потом проверь src/data и src/components».

Если GitHub нельзя:

1. Скопировать файлы по частям из `src/data` и `src/components`.
2. Начинать с `package.json`, `vite.config.ts`, `src/App.tsx`, `src/data/*`.
3. Потом компоненты.
4. Лучше копировать не один mega-file, а блоками по реальным путям файлов.

## 8. Как формулировать задачу новой сессии

Пример:

```text
Это проект «Карта русского баптизма». Сначала прочитай HANDOFF.md и ROADMAP.md. Работай полными файлами, если патч падает. Исторические данные держи в src/data. Савинский и Википедия не являются базовыми источниками. Проверяй build_project после изменений.
```
